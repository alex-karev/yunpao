# 阶段三：进行实验

用真实代码、数据和对照结果检验研究假设，回答“实际发生了什么，证据支持到什么程度”。

## 输入

选定的 `idea.json` 或等价实验方案，以及代码、数据、运行环境和资源约束。复现论文时还需论文来源、实现版本、目标实验和原文报告的指标。缺少执行必需信息时完成可做的准备，明确阻塞项。

## 流程

1. **冻结方案**：保存 idea 快照，确定基线、实验条件、数据划分、预处理、指标及方向、随机种子或重复次数、预算和停止条件。对照之间保持非研究变量一致；修改方案时创建新版本。
2. **准备资源**：记录数据来源、版本或校验值，保留原始数据；检查字段、缺失、重复和数据划分泄漏。固定代码版本、依赖环境、模型与实际执行命令。
3. **实现与小规模验证**：先运行最小样本，确认数据到指标的链路可用；对关键改动做受控对比，核验其确实影响目标计算或状态。命令能启动、参数能解析不代表方法已正确实现。
4. **执行对照**：按方案运行基线、候选和回答研究问题所需的消融。保存每个条件与重复的日志、原始输出、实际退出状态和产物；遵守预算，记录中断及恢复位置。
5. **核验结果**：确认所有计划条件完成、指标有效且评估口径相同；从原始结果计算差值和重复实验的波动，检查不同重复是否结论相反。小规模连通性测试和演示数据不能冒充正式结果；研究本身使用模拟时，预先声明模拟协议与适用范围。
6. **形成结论**：逐条回答假设得到支持、被反驳还是证据不足，关联具体结果，说明局限和下一步。未获得相应统计证据时只报告描述性发现；负结果同样保留。

## 输出与交接

在研究目录的 `experiments/<run-id>/` 下保存：

- `experiment-plan.json`：idea 快照、实验矩阵、数据与代码标识、环境、命令、指标、预算和停止条件。
- `metrics.json`：按条件和重复记录实际指标、退出状态及对应原始产物路径；汇总值由这些记录计算。
- `report.md`：执行状态、结果对比、对假设的判断、证据局限、失败项与恢复位置。
- `logs/` 及必要的原始预测、检查点或其他结果文件。

把 `report.md` 与证据文件交回“思考 idea”阶段，供下一轮改进；代码、数据或方案变化后，不能把旧结果当作新方案结果。

## 可选的 YunPao 执行层

已有 YunPao 环境时，确认目标服务器与会话，在 `yunpao.toml` 中配置实验动作和需拉取的产物，再通过 `yunpao run`、`logs` / `watch`、`pull` 执行、观察和取回结果。记录会话、动作及远程任务标识，恢复前先核对任务是否仍在运行。

后台任务启动成功不等于实验完成。由实验脚本保存真实退出状态和完成标记，并核验完整结果；不能只依据 YunPao 的“Done”提示或日志中的退出码行判断成功。没有 YunPao 时使用项目已有的本地或集群执行入口。

## 完成标准

计划内对照已完成，结果可追溯，结论与证据一致。流程完成与假设成立分别报告：假设被反驳也可以是完成的实验。若预算耗尽、任务失败或证据缺失，标为 `incomplete`，保留部分结果和恢复位置，不改动假设或评估标准来制造成功。
