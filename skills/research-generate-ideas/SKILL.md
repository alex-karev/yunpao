# 阶段二：思考 idea

把文献依据转为一个具体、可检验且资源可达的研究方案，回答“改进什么、为什么可能有效、如何验证”。

## 输入

第一阶段的 `papers.json` 与 `survey.md`，或用户提供的等价文献依据；研究目标、数据和算力约束。可选已有 idea、讨论意见或实验报告。沿用输入所在的研究目录。

## 流程

1. **定位问题**：从证据中提炼方法局限、结果矛盾或未覆盖场景，区分已知事实、解释和待验证假设。用户已有 idea 时先保持其原意，记录尚未明确的部分。
2. **生成候选**：围绕具体问题提出少量差异明确的方案。可考虑替换薄弱机制、简化组件、迁移理论或引入反馈；说明改变的计算或决策过程，避免仅堆叠模块名称。
3. **检查重叠**：比较最接近工作的研究问题、核心机制和应用条件，必要时补充检索。逐篇记录相同点、不同点及证据；检索相似度只用于找候选，不能作为创新性结论。
4. **比较取舍**：从证据支持、贡献大小、可证伪性、实现成本和数据可得性评估候选，保留主要反对意见与失败条件。用户未指定方案时给出推荐及理由。
5. **形成方案**：为选定候选写出研究问题、假设、方法、预期贡献、基线、数据、指标和资源预算，并设计能够支持或推翻核心假设的最小对照实验。

## 输出与交接

在研究目录的 `ideas/` 下保存：

- `ideas.md`：候选比较、推荐理由、与最近工作的差异、证据不足处及待解决问题。
- `idea.json`：包含 `status`、`question`、`hypothesis`、`method`、`expected_contribution`、`related_work`、`evidence_refs`、`experiment_plan`、`risks`。实验方案写明数据及划分、基线和对照条件、指标及优化方向、支持与反驳判据、预算与停止条件。

证据引用沿用第一阶段论文 ID；实验反馈引用具体运行及结果文件。将选定的 `idea.json` 交给“进行实验”阶段。后续修订保留版本及修改原因。

## 完成标准

核心机制清楚，贡献与已有工作可比较，假设有可执行的验证方式。“在本次检索范围内未找到直接重叠”不等于证明首创。证据、数据或预算仍缺失时标为 `incomplete` 并保留草案；不把预期收益写成实验结果。
