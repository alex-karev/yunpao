# 阶段一：收集论文

把研究主题转为可追溯的文献依据，回答“已有工作做了什么，哪些问题仍未解决”。

## 输入

研究主题或问题；可选的种子论文、现有文献库、年份范围、重点方向和数量目标。复用用户指定的研究目录，未指定时使用项目内的 `research/<topic-slug>/`。

## 流程

1. **确定范围**：提取问题、任务、方法和场景关键词，列出检索式及筛选标准。优先复用已有论文，再补充缺口。
2. **检索扩展**：使用当前可用的学术检索工具，结合种子论文的参考文献与后续引用扩展；同时关注代表性工作和近期进展。
3. **归一去重**：按 DOI、arXiv ID、规范化标题合并同一工作；保留来源、版本和获取状态，不因缺少 PDF 或引用量低而直接丢弃相关论文。
4. **阅读取证**：提取研究问题、核心方法、数据集、基线、指标、主要结果及局限。每个判断关联论文 ID 和实际读到的章节、页码或原文位置；只读到摘要时明确标注。
5. **整理脉络**：按任务或方法归类，对比方法、数据和评估设置，整理关键分歧与潜在空白。用表格或简单关系描述即可；按需要再构建知识图谱。

## 输出与交接

在研究目录的 `papers/` 下保存：

- `papers.json`：包含 `status`、`query`、`search_scope`、`papers`、`gaps`。每篇论文记录稳定 `id`、标题、年份、来源 URL、可用标识符、阅读范围、方法、发现、局限及证据位置；未知字段留空并说明原因。
- `survey.md`：简短综述，包括研究脉络、方法对照、未解决问题、检索范围和证据缺口。论断使用 `[paper:<id>]` 引用清单中的论文。

将这两份文件交给“思考 idea”阶段。已下载的全文和解析文件保留路径，避免重复获取。

## 完成标准

论文可去重定位，核心论断有来源，研究空白区分“原文明确指出”和“基于对比提出的推测”。未达到用户明确要求或关键证据不足时标为 `incomplete`，说明已完成内容及补充方向；不编造文献、全文内容或领域覆盖程度。
